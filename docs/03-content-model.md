# 03 · Content model

The course lives as YAML in `content/`. The pipeline (`docs/04`) validates it, annotates every Italian token, runs the checks, renders audio and compiles one SQLite **content pack** that the app reads. This document defines the source formats, IDs, the answer-pattern language and both databases. The worked example is Unit 2, Lesson 1: `content/units/02-al-bar/`.

**The seed files are normative for shapes.** Where an example here and a seed file differ, the seed file wins and this document is updated in the same change.

## IDs

IDs are permanent, lowercase ASCII, and unique across the course. Slugs strip accents, map an apostrophe to `-`, and map spaces to `-`. If two IDs would collide, the build fails and the author adds a `~sense` suffix. "Permanent" starts at the first release build (`ids.lock`): draft IDs may change until their file is first approved, and the golden lesson keeps its gaps (`ex12`, `ex16`) to show that dropped IDs are never reused.

| Thing | Pattern | Examples |
|---|---|---|
| unit | `uNN` (`u99` = final review) | `u00`, `u02`, `u99` |
| lesson | `uNN.lK` | `u02.l1` |
| lesson step | `uNN.lK.step-<kind>[-N]` | `u02.l1.step-story`, `u02.l1.step-practice` |
| unit-level step (generated, `docs/06` § Unit-level steps) | `uNN.step-opener`, `uNN.step-conversation-N`, `uNN.step-talk`, `uNN.step-writing`, `uNN.step-relay`, `uNN.step-check`, `uNN.step-fluency` | `u02.step-conversation-1`, `u02.step-check` |
| text (lines are `<textId>#n`, 1-based) | `uNN.lK.<name>`, `uNN.task.<name>`, `<exerciseId>.audio` | `u02.l1.story`, `u02.l1.story#3`, `u02.task.menu`, `u02.check.01.audio` |
| exercise | `uNN.lK.exNN`, `uNN.lK.qN` (story questions), `uNN.task.<name>`, `uNN.check.NN`, `pl.NN`, `fin.<section>.NN` | `u02.l1.ex07`, `u02.task.conv1` |
| generated exercise | preview: `<stepId>.b<k>.match`, `<stepId>.b<k>.<itemId with ":" replaced by "-">`; review cards: `gen:<skill>:<itemId>` | `u02.l1.step-preview.b1.match`, `u02.l1.step-preview.b1.w-cornetto`, `gen:recall:w:cornetto` |
| task file / check / note | `uNN.task` / `uNN.check`, `final`, `placement` / `uNN.lK.note[-N]` | `u02.task`, `u02.check`, `u02.l1.note` |
| word / chunk / grammar / sound | `w:` / `c:` / `g:` / `s:` + slug | `w:cornetto`, `w:caffe`, `c:quant-e`, `c:come-si-dice`, `g:indefinite-article`, `s:double-consonants` |
| homograph sense | `w:<slug>~<sense>` | `w:pesca~fruit`, `w:porta~door` |
| can-do | `cd:<slug>` | `cd:order-food-drink` |
| syllabus item | `sy:<area>.<slug>` (areas `gr`, `fn`, `tp`, `ss` sounds/spelling/register, `cefr`, `ex`) | `sy:gr.articles`, `sy:fn.greet-goodbye` |
| character | `ch:<slug>`; the reserved speakers `narrator` and `announcer` are written bare in YAML and stored as `ch:narrator`, `ch:announcer` | `ch:marco`, `ch:giulia` |
| topic | `topic:<slug>` | `topic:food-drink` |
| country | ISO 3166-1 alpha-2, lowercase; `gb-eng`, `gb-sct`, `gb-wls`, `gb-nir` for the UK nations | `us`, `gb-wls` |
| audio | `a:<12 hex of sha256>` (generated); its file is `<12 hex>.m4a` | `a:3f9c0e1a2b4d` → `3f9c0e1a2b4d.m4a` |

**Display forms.** Items carry generated display forms. Nouns always show with the **definite article** (`il cornetto`, `la spremuta`); where the article hides the gender, the display adds it (`l'acqua (f)`), and nouns for people show both genders (`l'amico / l'amica`). An article directly before a noun item, or before an adjective and a noun item, is part of that noun until the article's own unit (*un/una*: Unit 2; *il/la/lo…*: Unit 3; the lexical-article rule in `docs/04`), so cards may show it from Unit 0. The indefinite form (`un cornetto`) is also stored, for generated answers.

## Syllabus: `syllabus/a1-syllabus.yaml`

The A1 inventory is encoded from the plan's A1 syllabus tab, in our own words. Each entry says where the sources stand, what the course decides and which course objects cover it. Coverage check 1 (`docs/04`) traces every entry to *introduced*, *practised* and *assessed*. Entries sit in an `items:` list:

```yaml
items:
  - {id: sy:gr.articles, area: gr, label: "Articles, definite and indefinite", sources: {cils: R, celi: P, joint: P},
     course: "P, always taught with the noun", units: [u00, u01, u02, u03], covered_by: [g:indefinite-article, g:definite-article]}
```

`area` is `gr | fn | tp | ss | cefr | ex`. `covered_by` may reference grammar points (`g:`), sounds (`s:`), can-dos (`cd:`), topics (`topic:`), step kinds (`kind:story`), exercise formats (`format:dictation`) or check sections (`section:listening`). Two more links count as coverage: content tagged with the `sy:` ID directly, and a can-do whose own `syllabus` list names the entry. `units` is a list or `all`; `roles` (optional) narrows what check 1 requires (`[]` = informational only). The tracing rules are in `docs/04` § Check 1.

## Grammar points: `grammar/points.yaml` and `grammar/detection.yaml`

`points.yaml` holds the pedagogical decisions the content lead approves, in a `points:` list:

```yaml
points:
- id: g:indefinite-article
  title: un, uno, una, un'
  unit: u02
  status: P                    # P | R | chunk (taught as a whole; never counts as knowing the rule)
  syllabus: [sy:gr.articles]
  requires: [g:noun-gender]
  confusable: [g:definite-article]       # used for mixed practice
  about: Before Unit 2, un/una + noun is lexical (part of the noun).
```

`detection.yaml` holds how the annotator finds each point and which verb morphology it makes legal. Engineering owns it and refines it as content arrives, without reopening the approved `points.yaml`. Every point has an entry:

```yaml
rules:
- id: g:indefinite-article
  detect:
  - seq:
    - {pos: [ART, DET-INDEF], form: "^(un|uno|una|un')$"}
- id: g:essere-present-sg
  unlock:
  - {lemmas: [essere], morph: "ind\\+pres\\+[123]\\+s"}
  detect: none
```

- `unlock` lists Morph-it! feature patterns that become legal once the point is introduced (or, in its own lesson, from the story on; `docs/04` § Check 2): `{lemmas: [essere], morph: …}`, or `lemmas: "*"` for every verb. `morph` is a regular expression matched against the feature string after the colon (for example `ind+pres+3+s`).
- `status: R` points make their forms legal in **texts** (glossed) but never in **answers**.
- `detect` patterns are token sequences. Each matcher has optional `form` (regex on the lowercase surface), `lemma` (list), `pos` (Morph-it! category prefixes), `morph` (regex) and `optional: true`. A matcher matches a token only if every analysis left after disambiguation matches. Points that can't be detected reliably (stress, intonation, register) say `detect: none` and are traced through exercise targets instead.

## Items: `items/uNN.yaml`

```yaml
unit: u02
items:
  - id: w:cornetto
    it: cornetto
    pos: noun                  # noun verb adj adv prep conj pron det num interj
    gender: m                  # m | f | mf
    plural: cornetti           # or: invariable
    gloss: croissant
    alt_glosses: [pastry]      # also accepted in English answers
    note: In Bologna many people call it a brioche.
    topics: [topic:food-drink]
    status: P                  # shorthand for all four skills; or {read: P, listen: P, recall: R, speak: R}
    lesson: u02.l1             # where it is introduced; the checker verifies this
  - id: c:vorrei
    kind: chunk
    it: vorrei
    gloss: I'd like
    match: [vorrei]            # surface sequences the annotator recognises as this chunk
    exemplifies: [g:conditional-courtesy]   # optional: the rule it previews (no rule credit)
    status: P
    lesson: u02.l1
  - id: s:double-consonants
    kind: sound
    it: consonanti doppie
    gloss: double consonants
    pairs: [[pena, penna], [caro, carro], [sete, sette], [eco, ecco], [nono, nonno], [capello, cappello]]
    status: {listen: P}
    lesson: u00.l1
```

Optional fields:

- `articles: {indef: uno, def: lo}` overrides the computed articles.
- `forms` lists extra surface forms the resolver maps to this item (irregular verb forms, `amica` for `amico`). They resolve before any lemma lookup.
- `recall_answer` is an answer pattern for the generated recall cards when the default (`docs/06` § 1) doesn't fit. Its first expansion is the model answer. Example: `w:amico` accepts `{l'amico|l'amica|un amico|un'amica}`.
- `case_sensitive: true` (chunks) makes `match` case-sensitive: `c:e-lei` matches *e Lei* (formal you), not *e lei* (and she).
- `cognate: true` (transparent; may stay untaught), `false_friend: true` (always taught), `audio_say` (what TTS says for the item; default: the display form).

## Story bible: `story-bible.yaml`

Characters (age, role, origin, relationships, facts), places (real or fictional), the timeline (arrival in September, Luca's birthday in November, departure in December), `facts_to_check` (real-world facts the content lead verifies) and the **register matrix**: who says tu or Lei to whom. Rows have `from`, `to` (a character or `'*'`), `register`, `units`, and optionally a switch point (`then` + `switch_at` step). The precedence and switch rules are in the file's header and `docs/04` § Check 5. The critic agent uses everything else.

## Unit spec: `units/NN-slug/unit.yaml`

The unit spec is the contract every draft must satisfy. It extends the plan's example; see `content/units/02-al-bar/unit.yaml`. Required keys: `id`, `title {it,en}`, `episode`, `est_hours`, `lessons`, `can_do[]` (`id`, `text`, `scale`, `stretch`, `syllabus[]`), `grammar[]` (`id`, `status`), `chunks`, `items` (`new_words`, `topics`), `recycle_from`, `sounds`, `texts` (story count, word range, new-token maximum, listening kinds, real-world kinds), `tasks` (conversation, talk, writing, relay; `null` where the unit has none), `check` (`items`, `sections`) and `review`. Optional: `arc`, `notes`. The final review `u99` has `check: null` and names its final check in `tasks.final_check` instead.

### Texts

```yaml
text:
  id: u02.l1.story
  kind: story                  # story | dialogue | announcement | phone | message | real_world | model
  title: {it: "Bar Aurora", en: "Bar Aurora"}
  lines:
    - {speaker: narrator, it: "Marco è in un bar a Bologna. Si chiama Aurora.", en: "Marco is in a café in Bologna. It's called Aurora."}
    - {speaker: ch:giulia, to: ch:marco, register: lei, it: "Buongiorno! Cosa prende?", en: "Good morning! What will you have?"}
    - {speaker: ch:marco, to: ch:giulia, register: lei, it: 'Scusi, come si dice "croissant" in italiano?', en: 'Excuse me, how do you say "croissant" in Italian?', foreign: [croissant]}
```

Line fields: `speaker` (a character, `narrator` or `announcer`), `to` and `register` (`tu | lei`) whenever someone is addressed, `it`, `en`. Options: `foreign` (tokens excluded from the level gate and shown in italics), `gloss` (context glosses, e.g. `{da mangiare: to eat}`), `lemmas` (disambiguation, e.g. `{porta: w:porta~door}`), `recognise` (later forms to recognise only; each needs a `gloss`; `docs/04` § Annotation), `allow: {reason: …}` (a reviewed exception to the morphology gate), `say` (IPA overrides for this line, e.g. `{ancora: "anˈkoːra"}`), and `pause_ms` (extra pause after the line in audio). Real-world texts add `layout` (`docs/06` § Real-world reading).

Write numbers, times and prices in words in texts that will be voiced (`sei euro e venti`, not `6,20 €`), so audio, word timings and highlighting line up. Real-world layouts may show digits, because they aren't voiced.

### Exercises (fields shared by all formats)

```yaml
- id: u02.l1.ex01
  format: cloze                # docs/06 lists every format and its fields
  targets:                     # what this exercise trains; FSRS is updated for these (primary targets)
    - {item: g:indefinite-article, skill: recall}
  tags: [cd:order-food-drink]  # alignment: at least one can-do or syllabus ID
  source: u02.l1.story#3       # optional: the text line it reuses (cohesion rule 2)
  text: "Vorrei [[un]] cappuccino, per favore."
  prompt_en: "I'd like a cappuccino, please."
  hint: Cappuccino is masculine.                     # shown on request, and after a first wrong answer
  rule: un with most masculine nouns, una with feminine nouns (un' before a vowel).   # shown with the answer
  near: [{answer: "una", hint: "Una is for feminine nouns. Is cappuccino masculine or feminine?"}]
```

`near` lists anticipated wrong answers with a targeted hint; `outcome: almost` marks a near-miss that is nearly right (a wrong article on the right noun) rather than wrong. Hints must point at the problem without giving the answer away. `audio_after: true` plays the model answer after the learner answers.

Authors list only **primary targets**. The pipeline derives every other requirement (each word shown or expected) from the annotations and compiles it to `exercise_requires`, which drives eligibility (`docs/04` § Requirements).

Check, final and placement exercises add `score` (default 1). Talk, writing and conversation items may score more than 1; their content `points` are a list (see `docs/06`), not a score.

## The answer-pattern language

Accepted answers (`answer`, cloze gaps `[[…]]`, conversation `accept`, near-miss `answer`, `recall_answer`) are patterns that expand into a finite set of strings.

| Syntax | Meaning | Example → expansions |
|---|---|---|
| plain text | literal (case, punctuation and spacing are normalised before comparing; `docs/05`) | `Vorrei un caffè` |
| `{a\|b}` | alternatives (may contain sequences and nest) | `{vorrei\|prendo} un caffè` → 2 |
| `(…)` | optional (may contain alternatives) | `un caffè( per favore)` → 2; `( {per favore\|grazie})` → 3 |
| `[…]` | **focus**: graded strictly (no typo tolerance) | `[un] cornetto` |
| `{m:…\|f:…}` | gendered alternative; both accepted unless the learner asked for strict forms. Every alternative of the group carries `m:` or `f:` | `sono {m:americano\|f:americana}`, `sono {m:nato\|f:nata} a Toronto` |
| `{NAME}` | any 1–3 words | `mi chiamo {NAME}` |
| `{NUMBER}` | an integer in digits or Italian words, one token (`30`, `trenta`, `ventitré`) | `ho {NUMBER} anni` |
| `{ME.nationality}`, `{ME.home}`, `{ME.country}` | the learner's onboarding answers, in their gender form; `{ME.home}` also accepts the country's `alt_home_phrases`; `{ME.nationality}` is a gendered pair (`{m:americano\|f:americana}`), so strict forms apply to it | `abito {ME.home}` → `abito negli Stati Uniti` |
| `\{` `\[` `\(` `\|` (any `\x`) | escaped literal | `\{x\}` → `{x}` |

**Expansion order:** alternatives left to right; an optional group *present* before *absent*. The **first expansion is the model answer**: it is what learners are shown (with personal slots filled in), and it is the only expansion the production gate checks. Other expansions exist to accept correct answers and may use words from later units. A gap `[[…]]` is entirely focus. **An expansion never mixes genders:** a combination that takes an `m:` alternative in one group and an `f:` alternative in another is not generated (`sono {m:americano|f:americana} e sono {m:nato|f:nata}` → 2 expansions, not 4), because both refer to the same person. A pattern may expand to at most **512** strings, counted after that rule and before personal slots are filled; the build fails beyond that. Without a learner (the pipeline, the review pages), a slot stays one token written as its placeholder (`mi chiamo {NAME}`). Slot-like names that aren't slots are errors (`unknown slot {Name}`), not literals: a one-alternative `{…}` whose content is a slot name in another case (`{Name}`, `{number}`, `{me.home}`), starts with `ME.` in any case (`{ME.city}`), or is written in capitals, digits, `_` and `.` (`{NOME}`, `{NAME2}`). Other one-alternative groups are literals (`{Ciao}` → `ciao`). `fixtures/grading/patterns.json` is the reference.

**Personal slots, edge cases:**
- The learner chose "Another country": `{ME.home}` and `{ME.country}` accept any 1–4 words and `{ME.nationality}` any one word; the model answer shows the story's example (`in Canada`, `canadese`) labelled "for example".
- No name given: the model answer for `{NAME}` uses *Marco* (masculine forms chosen) or *Sara* (feminine), labelled "for example". `{NAME}` still accepts any 1–3 words when a name is set.
- The examples are content: the app passes them to LearningCore from the pack (the `ca` row of `countries` and the names of `ch:marco` and `ch:sara`), so no Italian is hard-coded in Swift.
- The learner chose "both forms" (or didn't say): `{m:…|f:…}` accepts both and the strict-forms setting has no effect. The model answer itself (audio, the production gate) uses the masculine form; the answer **shown in feedback** joins both forms (*nato/nata*, *americano/americana*; `docs/05` § Typed answers).
- `{NUMBER}` has no learner value: a model answer shows it as `…`.

## Review status and approval

Every lesson, task, check, unit spec, items file, `points.yaml`, the syllabus, the story bible and `countries.yaml` carries:

```yaml
review:
  status: draft                # draft | in-review | approved
  by: null                     # content lead's name, set on approval
  date: null
  hash: null                   # docs/04 § Approval hash
```

Only humans change `review` by running `uv run content approve <file> --by "<name>"` or `content reopen <file>`; the command refuses to run from an agent's shell (`docs/04` § Commands). The PreToolUse hook blocks agent edits to approved files, and `content lint` fails if an approved file's hash no longer matches. The pack build includes only approved content in release mode (`content build --release`); dev builds include drafts and mark them in the app's Debug overlay.

## Annotation lock files

`content annotate` (`make annotate`) writes `content/.annotations/<same path>.json` for every file with Italian text: per token its surface, character span, chosen lemma and morphology, item ID, chunk ID, grammar detections and flags (new, recognise-only, foreign, name, number, lexical article). The lock files are committed and reviewed like code; never edit them by hand. `content annotate --check` (run in CI) regenerates them and fails on any difference.

## The compiled content pack

`schemas/content-pack.sql` is the **normative** schema; Python creates the database from it and Swift reads it. Bump `meta.schema_version` (an integer) when the schema changes incompatibly. The app refuses a pack whose schema version differs from the one it was built for.

Main tables: `meta`, `units`, `can_dos`, `syllabus_items`, `syllabus_trace`, `items`, `item_skills` (status, plus a `scheduled` flag per item and skill, `docs/05`), `item_requires`, `forms`, `sounds`, `lessons`, `steps` (kind, JSON payload, strand, estimated seconds), `step_introduces`, `texts`, `text_lines`, `tokens` (with `start_ms`/`end_ms`), `text_requires`, `grammar_notes`, `note_items`, `exercises` (format, role, JSON payload), `exercise_targets`, `exercise_requires`, `exercise_tags`, `assessments` (placement and final check), `characters` (including `ch:narrator` and `ch:announcer`), `countries`, `audio`.

Payload JSON shapes are defined per step kind and format in `docs/06`. They are decoded into `Codable` types in LearningCore; unknown keys are ignored and missing required keys are a decode error that fails the pack tests (`fixtures/packs/mini-payloads.json` on Linux, the SQLite pack in Storage tests).

## The learner database (reference DDL; GRDB migrations implement it)

```sql
-- the source of truth: immutable, append-only, synced

  id            TEXT PRIMARY KEY,      -- lowercase UUID
  at            INTEGER NOT NULL,      -- ms since epoch, UTC
  tz_offset_min INTEGER NOT NULL,      -- device UTC offset when the event happened (local-day maths)
  type          TEXT NOT NULL,         -- docs/05 § Events
  device_id     TEXT NOT NULL,
  schema        INTEGER NOT NULL,      -- payload schema version
  pack_version  TEXT NOT NULL,
  payload       TEXT NOT NULL,         -- JSON
  origin        TEXT NOT NULL CHECK (origin IN ('local','remote'))
);
CREATE INDEX events_order ON events(at, id);

-- derived: rebuildable at any time from events + pack
CREATE TABLE memory (item_id TEXT, skill TEXT, stability REAL NOT NULL, difficulty REAL NOT NULL,
  last_review INTEGER NOT NULL, due INTEGER NOT NULL, reps INTEGER NOT NULL, lapses INTEGER NOT NULL,
  PRIMARY KEY (item_id, skill));

  via TEXT NOT NULL,                   -- preview|story|note|sounds|placement|catchup|debug
  PRIMARY KEY (item_id, skill));

  cursor INTEGER NOT NULL DEFAULT 0);  -- docs/05 § Replay: derived from attempts, never stored by events

  check_score REAL, check_passed INTEGER, completed_at INTEGER);              -- best check score across attempts

CREATE TABLE exercise_history (exercise_id TEXT PRIMARY KEY, last_at INTEGER NOT NULL, attempts INTEGER NOT NULL, first_try_correct INTEGER NOT NULL);

  active_seconds INTEGER NOT NULL, steps_completed INTEGER NOT NULL, cards_reviewed INTEGER NOT NULL);

-- settings: per-key last-writer-wins
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at INTEGER NOT NULL,
  device_id TEXT NOT NULL, scope TEXT NOT NULL CHECK (scope IN ('synced','device')));

-- sync bookkeeping (docs/08)
CREATE TABLE sync_engine_state (id INTEGER PRIMARY KEY CHECK (id = 1), data BLOB);
CREATE TABLE cloud_system_fields (record_name TEXT PRIMARY KEY, data BLOB NOT NULL);
CREATE TABLE sync_pending (record_name TEXT PRIMARY KEY, kind TEXT NOT NULL, added_at INTEGER NOT NULL);

-- study telemetry bookkeeping (docs/12): device-local, never synced, never rebuilt
CREATE TABLE telemetry_sent (event_id TEXT PRIMARY KEY, batch_id TEXT NOT NULL, sent_at INTEGER NOT NULL);
```

Events are never updated or deleted; upload state lives in `telemetry_sent`, sync state in `sync_pending`. Bump `derived_version` whenever reducer logic changes. On launch, a mismatch of `derived_version`, or of the pack's `meta.content_hash` against `derived_meta.content_hash`, triggers `rebuildAll()`.
