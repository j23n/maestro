# 07 · UI and design system

The design direction is **Libro**: reading-first, a serif for Italian, warm terracotta accents and a lot of white space. The app should feel like a well-made book that talks back, not a game.

- `design/screens/*.png` — reference renders at 2× (Moka in place of Tito). **Their text is placeholder** that predates the final syllabus (8 units, *c'è*, *nel*…): copy layout, spacing and hierarchy, never words.
- `design/source/*.dc.html` — the canvas sources: exact sizes, paddings and colours are in their inline styles.
- `design/tokens.json` — colours (light; a dark proposal; five values changed from the canvas for contrast, listed in `$contrastChanges`), type scale, spacing, radii and sizes. Implement it as Swift constants in `DesignSystem/Tokens.swift` and keep the two in sync.
- `design/fonts/` — Literata and Instrument Sans (OFL). Register them at launch with `CTFontManagerRegisterFontURLs` on every platform (no Info.plist keys; `ATSApplicationFontsPath` is easy to get wrong on macOS), and use them through `Font.custom(_:size:relativeTo:)` so Dynamic Type works on iOS.
- **Text size:** every font size is multiplied by the `display.textScale` setting (0.85–1.6, an environment value). On iOS and iPadOS it applies on top of Dynamic Type; on macOS, which has no Dynamic Type, it is the only text-size control (View → Text Size).
- **App icon:** Moka (hello pose) on the `surface` colour, a single 1024 pt master rendered from `design/mascot/moka-hello.svg` into a single-size app icon in `Assets.xcassets` (task M6.2), plus the Mac's sizes (16–512 pt at 1× and 2×); every PNG is opaque RGB. TestFlight uploads need it.
- **Launch screen** (iOS and iPadOS; M6.2): the `background` colour only, light or dark, through the `UILaunchScreen` dictionary in `Config/Italiano-Info.plist` and the `LaunchBackground` colour set, which `scripts/gen-tokens.py` generates from `tokens.json` like `AccentColor`. It matches the loading screen RootView draws next (Moka asleep on `background`), so nothing changes colour at launch. macOS has no launch screen.
- `design/mascot/` — Moka in four poses (SVG; import with "Preserve Vector Data") plus alternates.

## Navigation

- `TabView` with `.tabViewStyle(.sidebarAdaptable)` and tabs **Today**, **Course**, **Words**, **Settings**. Icons: sun, book (open), list, gear.
- The lesson player covers everything (`docs/02`). Close (X) saves and returns.
- Onboarding runs on first launch: Welcome → Why Italian? → Your name (optional, used in role-plays) → Which forms fit you (masculine: *nato, americano* · feminine: *nata, americana* · show me both) → Where do you live? (country list with Italian names) → Weekly goal (3–7 days, default 5) → Have you studied Italian before? (no → Unit 0; yes → placement, when the pack has placement questions) → [study builds: research consent] → Today.
- **Mac menu bar:**
  - **Lesson menu:** Check (Return), Show Hint (⇧⌘H; ⌘H is the system Hide), Listen Again (⌘L), Show Answer (⇧⌘A), Close Lesson (Esc).
  - **View menu:** Bigger Text (⌘+), Smaller Text (⌘−), Actual Size (⌘0) and Show English (⇧⌘E).
    The text-size items step `display.textScale` through 0.85, 0.9, 1.0, 1.1 … 1.6 (`TextSizeCommand`); Show English toggles the story's or conversation's English lines.
  - The Lesson items act on the screen in front (focused scene values published next to the buttons that do the same, which keep their own shortcuts for iPad keyboards); an item is disabled when the screen has no such action. Writing tasks don't publish Check, so Return still makes a new line there.
  - The standard App menu includes **Settings…** (⌘,), which opens the `Settings` scene.
- **Settings → About → Acknowledgements** (`Acknowledgements.swift`): every row of `docs/13` § Licences is credited or listed as not credited with a reason (a test reads the table); the fonts' OFL texts come from `Resources/Licenses`, GRDB's MIT notice is carried in the code.
- **Window:** minimum window 900 × 620. The app restores the last tab and remembers window size.

## Layout rules

- **Compact width** (iPhone, iPad Slide Over): screen padding 24, single column.
- **Regular width:** content column max 720 pt, centred. The story reader and conversation use two panes with a hairline `divider` between (right pane ~ 34% width, min 320).
- **Large text:** at accessibility sizes, side-by-side layouts stack and option cards grow vertically. Nothing truncates Italian text (no `lineLimit` on Italian).
- **Keyboard:** the answer field stays visible above the keyboard (iOS), and Check and accent keys sit above the keyboard on iPhone.
- **Dark mode** uses the dark tokens.
- **Contrast:** text ≥ 4.5:1 and control boundaries (input borders, switch tracks, option-card borders) ≥ 3:1 against their background. `divider` and `subtle` are decorative and exempt; `warning` is a border colour only (warning text uses `warningText`). `scripts/check-contrast.py` checks every token pair the UI uses; add a pair when a view combines two tokens in a new way, and record changed values in `tokens.json` (`$contrastChanges`).

## Copy

- English UI in sentence case; short, warm and plain. "Check", "Try again", "Show answer", "Continue".
- Italian appears only from the content pack, except fixed UI greetings (*Buongiorno*, *Buonasera*, *Bravo!*, *Indice*), which live in the String Catalog with an English comment.
- Moka speaks only in short italic lines: hints, notes and celebrations. Moka never scolds.
- Error and empty states say what happens next: "No reviews due. Your next review is tomorrow at 9."

## Accessibility (acceptance criteria for every screen)

- Every interactive element has a label and an identifier (`screen.element[.n]`).
- VoiceOver order follows the visual reading order; Italian is spoken by the Italian voice.
- Supports Dynamic Type from xSmall to AX5 without clipping.
- Contrast passes in light and dark mode.
- Reduce Motion: no mascot animation and no sliding panels (cross-fade instead).
- Full keyboard use on Mac and on iPad with a hardware keyboard.
- Audio is never the only channel: every audio prompt has a visible fallback after answering (transcript), except while a listening task is still unanswered.

## Visual verification

- **Snapshot tests** (swift-snapshot-testing 1.19, Swift Testing): every component and every exercise view in this matrix: iPhone compact light, iPhone compact dark, iPad regular light, iPad regular dark, and iPhone at AX5 (light). They use the mini pack, a pinned simulator runtime and `perceptualPrecision: 0.98`, so CI runners don't fail on anti-aliasing.
- **Simulator screenshots** through MobileBuildMCP (`build_run_sim`, `snapshot_ui`, `tap`, `screenshot`). Its `type_text` sends ASCII only and can't type à è é ì ò ù, so use the accent keys or an XCUITest for accented input.
- **Mac screenshots** through an XCUITest (`ItalianoUITests/MacScreens`) that saves `XCTAttachment`s, because MobileBuildMCP's UI automation is iOS-only.
- Save evidence to `artifacts/screens/<task-id>/` and compare it with `design/screens/` using the **ui-reviewer** subagent.
- The XCUITest screenshot runs (`ItalianoUITests/Screenshots`, `MacScreens`) drive the players with the Debug auto-answer bar (M6.3), so player screens carry it at the bottom trailing corner; it is left out of finished pages (Bravo!, Session complete). The ui-reviewer ignores it. Learner-path launches pin the kept Debug switches off (`-ITADebugShowAutoAnswer NO` and the others in docs/02).
